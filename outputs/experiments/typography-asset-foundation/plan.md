# Typography Asset Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish Inter as a deterministic WOFF2 web-font asset, expose only atomic typography tokens from Panda foundation, and make `Button.label` compose its typography from those tokens.

**Architecture:** A new `src/shared/fonts/` asset module owns raw sources, generated WOFF2 files, a generated manifest, `@font-face`, and versioned Node/Bun build scripts. `mise run fonts:build` and `mise run fonts:check` are thin entry points that invoke `src/shared/fonts/tools/build.ts` (the latter passes `--check`); all transformation, validation and drift detection live in that script and its focused modules. `.opencode/skills/build-web-font/SKILL.md` is an operator workflow only: it tells an agent when and how to invoke the commands, never reimplements their logic. The module is deliberately separate from both components and `styles/foundation`: the former owns assets and delivery, while foundation owns only reusable typographic values. Components compose those values at slots; the first proof is `Button.label`, not a global text-style API.

**Tech Stack:** React 19.3, Vite 8.3, PandaCSS 1.12, Bun 1.4, TypeScript 6, `wawoff2` 2.0.1, `fontkit` 2.0.4, Storybook/Vitest browser tests, Playwright.

**Spec:** `outputs/shared/notes/landing-system-roadmap.md` (next-cycle scope), plus the approved design baseline in this plan: atomic foundation tokens only; no Panda `textStyles`, no foundation roles such as `buttonLabel`/`heading-1`; variable Inter is the only runtime font for this experiment.

## Global Constraints

- Do not edit generated Panda files in `src/shared/styled-system/`; run `mise run gen` after theme changes.
- Use exact dependency versions and commit `bun.lock` with `package.json` changes.
- `mise` is the only task runner; do not add `package.json` scripts.
- Keep task names synchronized where documented: `.mise.toml`, `README.md`, `AGENTS.md`, `.agents/tooling.md`, and `.agents/workflows.md`; confirm `.husky/*` and `lint-staged.config.mjs` do not duplicate task lists.
- Fonts are an asset module, not a React component and not part of Panda foundation. Foundation owns tokens only; it must not know file paths, `@font-face`, font manifests, components, slots, variants, or CSS-property names.
- Use Inter’s two variable sources only: normal and italic, with `opsz` and `wght`; do not ship the downloaded static TTF collection.
- Raw sources must not live below Vite `public/`; Vite copies every public file to the production output.
- Generated WOFF2 and `manifest.generated.ts` are committed and writable only by the font build tool.
- `fonts:build` and `fonts:check` must remain thin mise tasks that invoke the versioned Bun script; the project-local skill invokes those tasks and contains no transformation logic.
- Runtime WOFF2 faces use `font-display: swap`; no preload and no Unicode subsetting in this experiment.
- Public CSS declares normal and italic faces with `font-weight: 100 900`; optical sizing remains browser-managed (`font-optical-sizing: auto`, the CSS default).
- Foundation contains atomic `fonts`, `fontSizes`, `fontWeights`, `lineHeights`, and `letterSpacings`; it contains no composite text styles or component/page roles.
- Continue the current conventions: longhand CSS properties only, component visual projection stays in each component recipe, and global `body` continues to select only the default `body` family token.

## Review Focus

- **Raw distribution accidentally remains public:** a production build must not contain the 20 MB static TTF bundle; Task 1 removes it and Task 7 checks the built asset inventory.
- **Variable axes are lost in conversion:** normal and italic WOFF2 must retain `opsz` and `wght`; Task 2 parses the generated bytes and asserts both axes.
- **A face is silently mismatched:** an italic source registered as normal, a family other than Inter, or an unexpected weight range must make `fonts:build` fail; Task 2 owns these validation tests.
- **A future edit makes generated artifacts stale:** `fonts:check` must fail on byte drift in either WOFF2 or the generated manifest; Task 3 tests both drift cases.
- **A component bypasses the foundation:** Button’s label must own all five font properties and `root` must own none; Task 6 asserts the complete slot/root split.

- [ ] **Step 3: Add the exact metadata parser dependency and implement conversion**

Add `"fontkit": "2.0.4"` to `devDependencies`, run `mise run install`, and commit the resulting `bun.lock` change. Keep existing `wawoff2` at `2.0.1`.

Implement these rules in `font.ts`:

1. Parse raw and WOFF2 bytes with `fontkit`.
2. Require `familyName === FONT_FAMILY`.
3. Require exactly the expected style (`normal` maps to an upright face; `italic` maps to italic).
4. Require `variationAxes` to include `opsz` and `wght`; require `wght.min === 100` and `wght.max === 900`.
5. Compress the original TTF bytes with `wawoff2.compress` and reject a result whose magic header is not `wOF2`.
6. Parse the compressed bytes again and apply the same axis/range validation. This is the proof that conversion preserves usable variable-font metadata.
7. Return buffers without timestamps or other build-time metadata. The function must not mutate source data or write files.

Use explicit error messages containing face id, source path, expected value, and observed value. Do not silently substitute static TTFs or omit a missing axis.
