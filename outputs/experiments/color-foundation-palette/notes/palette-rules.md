# Palette And Role Rules

Правила foundation-цветов, проверенные в эксперименте. Это вывод эксперимента, а
не изменение постоянных правил `wiki/`.

## Два уровня

`theme.tokens.colors` собирается из двух явно разделённых наборов:

1. `staticPalette` — примитивная палитра (`palette.ts`).
2. `roles` — системные роли (`colors.ts`).
3. `shadowColors` — цвета теней, вне scope этого эксперимента.

`themeConditions` (`_light` / `_dark`) остаются в `colors.ts`; другие группы
используют их, но не объявляют повторно.

## Правила палитры

1. У каждого семейства фиксированный набор шагов `50, 100, …, 950` (11 шагов).
   `PALETTE_STEPS` — единый источник этого набора.
2. Токен палитры не зависит от темы: одно значение, без `light`/`dark`.
3. Семейство добавляется только при наличии потребителя или доказанной системной
   потребности. Палитра не растёт «на будущее».
4. Значения проектируются от уже существующих цветов; все текущие значения ролей
   закреплены на точных шагах.
5. Свободные шаги интерполируются в OKLCH с монотонной светлотой; hue и chroma
   интерполируются между anchor-шагами и затухают к краям шкалы.
6. Палитра — источник ингредиентов, а не публичный API компонента. Обычный путь
   потребления — роли. Прямая ссылка на палитру допустима для `colorPalette` и
   для документированных исключений.
7. Native `colorPalette` ограничен семействами палитры через
   `theme.colorPalette.include`; роли в него не попадают.

## Правила ролей

1. Роль — системное имя, а не часть компонента и не CSS-свойство.
2. Роль остаётся статической парой `*.light` / `*.dark` (текущая модель не
   меняется); условие остаётся в property на месте использования.
3. Значение роли ссылается на токен `staticPalette`. Literal допустим только как
   задокументированное исключение.
4. Роли группируются по смыслу: `surface`, `ink`, `line`, `accent`, `status`.
5. Имена не используют `hover`, `disabled`, `focus` и не совпадают с именами
   CSS-свойств.
6. Имя группы ролей не должно совпадать с именем семейства палитры: `danger` как
   группа ролей конфликтует с семейством `danger`, поэтому роль называется
   `status.danger`.

## Что допустимо как условная семантика

- Роль допустима только для application-wide смысла: поверхность, текст,
  граница, акцент, статус.
- Компонентные и одноразовые цвета не становятся ролями и не влияют на палитру.
- Семейства палитры консервативны: сейчас `neutral`, `brand`, `danger`.
- Новое семейство или роль появляется вместе с потребителем и тестом.

## Итоговый словарь

Палитра:

- `neutral`, `brand`, `danger` × `50…950`.

Роли (пары `light` / `dark`):

| Роль | Light | Dark | Источник |
| --- | --- | --- | --- |
| `surface.base` | `#FFFFFF` | `#0D1016` | `neutral.50` / `neutral.950` |
| `surface.raised` | `#F7F8FA` | `#151A22` | `neutral.100` / `neutral.900` |
| `ink.strong` | `#1A1A1A` | `#F3F5F8` | `neutral.800` / `neutral.200` |
| `ink.soft` | `#666666` | `#A8B0BB` | `neutral.500` / `neutral.400` |
| `line.strong` | `#1A1A1A` | `#4A5462` | `neutral.800` / `neutral.600` |
| `line.soft` | `#EDEFF2` | `#212831` | `neutral.300` / `neutral.700` |
| `accent.base` | `#4A9FD8` | `#5AB0EA` | `brand.500` / `brand.400` |
| `accent.deep` | `#1B5FA8` | `#1E6BB8` | `brand.800` / `brand.700` |
| `status.danger` | `#C0392B` | `#F87171` | `danger.700` / `danger.300` |

Роль намеренно может ссылаться на тот же шаг, что и другая роль: `ink.strong` и
`line.strong` в light-теме используют `neutral.800`. Это не дубль значения, а
разные смыслы с одинаковым визуальным требованием.
