# Эксперимент: ButtonIcon

**Статус:** completed (2026-09-25).

Основной результат — самостоятельный компонент `ButtonIcon` (квадратная кнопка
только с иконкой, обязательные `icon` и `label`), выведенный из существующих
деталей проекта агентом-билдером в отдельном чистом контексте. По ходу найден и
решён реальный пробел сборки пресетов Panda. Итоговые выводы —
`notes/retrospective.md`.

Кнопка только с иконкой — отдельный компонент, отложенный по итогам
`button-icon-composition`: в ретроспективе он явно вынесен за рамки того
эксперимента как другая задача.

Ветка: `experiment/button-icon` от `main` (коммит `b1f3c62`, рабочая директория
чистая).

## Вопрос

Можно ли собрать `ButtonIcon` — кнопку с иконкой без видимого текста — из уже
существующих в проекте деталей, правил и заметок, не изобретая лишних сущностей;
и достаточно ли текущих правил, заметок и кода, чтобы вывести API, оформление,
композицию и accessibility компонента самостоятельно.

## Scope

В рамках:

- сам компонент `ButtonIcon` в `src/shared/components/`;
- его API, оформление, композиция с `Icon` и поведение;
- доступность: доступное имя, клавиатурное управление, фокус, `disabled`;
- демонстрация компонента и проверки, принятые в проекте;
- переиспользование существующих деталей `Button` / `Icon` и правил пресетов.

Вне рамок:

- миграция потребителей за пределами демонстрации;
- универсальная система композиции компонентов;
- новые варианты `Button`, не нужные для `ButtonIcon`;
- типографика, `Input`, `Card` и прочие задачи roadmap.

## Модель

Заранее не задаётся. API, оформление и композиция выводятся из существующих
правил, заметок и кода; решения фиксируются по ходу работы и в результатах.
Готовых решений в этом документе намеренно нет — иначе вопрос эксперимента
теряет смысл.

## Критерии успеха

- `ButtonIcon` доступен потребителю как самостоятельный компонент.
- Поведение нативного `<button>` сохранено: атрибуты, события, `ref`, `disabled`.
- У кнопки есть доступное имя; иконка декоративная и его не дублирует.
- Размер, геометрия и цвет иконки согласованы с существующими правилами, а не
  выбираются потребителем вручную.
- Компонент следует принятой в проекте организации (модуль, preset, stories,
  тесты) и не дублирует существующие сущности без обоснования.
- Обязательные проектные проверки проходят.
- Выводы зафиксированы; закрытие — по прямой команде пользователя.

## Состояние (2026-09-25)

- Компонент реализован и закоммичен: `src/shared/components/button-icon/`
  (компонент, preset, barrel, 10 stories, 15 контрактных и 7 composition-тестов).
- Регистрация пресетов приведена к единой модели: компоненты объявляют рецепт
  напрямую, словари собираются явно в `src/shared/styles/index.ts`
  (`componentsPreset`); добавлен регрессионный тест
  `src/shared/styles/presets.test.ts` (RED → GREEN).
- Правило уточнено в `.agents/project.md`: владение пресетом, роль точки сбора,
  запрет прямого подключения нескольких `theme.slotRecipes` и component overrides.
- Проверки на закрытии — зелёные: `check` (104 unit / 26 browser), `check:types`,
  `check:lint`, `check:format`, `check:deps`, `build`, `storybook:build`,
  `test:visual`.
- Открытые ограничения: публичная поверхность точки сбора расширена техническими
  экспортами; оси `tone`/`size` и геометрия требуют дизайн-подтверждения;
  клавиатурная активация отдельным сценарием не покрыта. Подробнее —
  `notes/retrospective.md`.
- Эксперимент закрыт по прямой команде пользователя. Ветка влита в `main`
  fast-forward; ветка эксперимента удалена.
