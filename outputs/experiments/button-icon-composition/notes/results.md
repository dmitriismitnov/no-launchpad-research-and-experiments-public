# Результаты

Состояние на 2026-09-25. Реализация выполнена; эксперимент **не закрыт** —
закрытие по прямой команде.

## Что сделано

- Публичный `Button` принимает `prefixIcon?: IconName` / `suffixIcon?: IconName`
  и сам создаёт `Icon` (`sm → sm`, `md → sm`).
- Соответствие `ButtonSize → IconSize` живёт в модуле `Button`
  (`ICON_SIZE_BY_BUTTON_SIZE`) и не зависит от совпадения названий.
- Цвет по-прежнему задаёт `Button`, `Icon` наследует через `currentColor`;
  иконки декоративные, доступное имя — у кнопки.
- Приватный `_Button` (`ReactNode`) не экспортируется; проверено тестом
  (namespace модуля = `["Button"]`).
- Мигрированы `App.tsx` и `Button.stories.tsx`; добавлены истории `WithIcons` и
  `IconOnly` с play-проверками.
- Добавлены контрактные тесты `Button.composition.test.tsx` (7 тестов), включая
  проверки типов через `@ts-expect-error`.

## Ответы на цели

1. **Связать `Button` и `Icon`** — сделано: потребитель задаёт имя, `Button`
   владеет размером и цветом; ручное создание `Icon` ушло.
2. **Хватает ли контракта `Icon`** — да. `IconName` уже экспортирован и
   достаточен для типизации; `IconSize` закрывает подбор размера; `currentColor`
   закрывает цвет; `className` и стандартные атрибуты доступны. Runtime-список
   имён или map не понадобились (см. `notes/comparison.md`).
3. **Польза приватной/публичной версии** — публичный API у обоих вариантов
   одинаков, поэтому разделение даёт только внутреннюю структуру. Доказуемой
   текущей пользы нет; цена — 20 строк и лишний слой. Подробно:
   `notes/comparison.md`. Решение и рекомендация зафиксированы там же.

## Изменение по ревью: удаление `tone="icon"`

`tone` — цветовая ось, а `icon` задавал форму (квадрат `x16`, `paddingInline: x0`)
и тип содержимого. После того как `Button` начал владеть иконкой, это стало
заметно, и кнопка только с иконкой вынесена в отдельный будущий компонент.

- `ButtonTone` → `primary | secondary | ghost`; из recipe удалён вариант `icon`
  и оба compound-variant; `staticCss` обновлён.
- `App.tsx` и stories обновлены; `IconOnly` удалён, проверка наследования цвета
  перенесена в `WithIcons`.
- Visual baseline пересмотрен: убрана квадратная icon-only кнопка (54 px),
  остальное не изменилось.
- Критерий «кнопка только с иконкой» вынесен из рамок эксперимента.
- TDD: RED зафиксирован (3 поведенческих теста падали; `check:types` давал 2
  unused `@ts-expect-error`), затем GREEN.

## Решения (rulings)

- Размеры: сопоставление живёт в `Button`, не выводится из имён; начально
  `sm → sm`, `md → sm`.
- Публичные имена props сохранены, изменён тип (`ReactNode → IconName`) —
  осознанный breaking change; все потребители мигрированы.
- Runtime-map имён в v1 не добавлялась.
- Размеры проверяются поведенчески (`renderToStaticMarkup`), без экспорта
  внутренностей.
- Судьба `_Button`: оставлен (согласованная модель), с рекомендацией свернуть,
  если не появится конкретный неиконочный потребитель слота.

## Открытые вопросы

- Нужен ли node-based слот на самом деле (иконочный `Icon` его пока не требует).
- Достаточно ли `sm → sm`, `md → sm` на реальных макетах.
- Отдельный компонент для кнопки только с иконкой: форма, размеры, состояния
  (вынесен из рамок после удаления `tone="icon"`).
