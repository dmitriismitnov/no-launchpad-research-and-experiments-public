# Script-First Flows and Agent Workspace

Общая заметка вне эксперимента. Backlog: две идеи об организации работы
агента — детерминированные флоу на скриптах и рабочее пространство проекта для
агента.

Материал — направление и backlog, а не план и не обязательство. При появлении
конкретной задачи тема может стать отдельным экспериментом.

## Часть 1. Флоу на скриптах

Идея: большая часть флоу должна быть реализована скриптами. Агент в своих
скиллах эти скрипты вызывает. Если возможностей целевого скрипта не хватает,
агент:

1. делает копию скрипта;
2. добавляет в копию нужную возможность;
3. выполняет задачу модифицированной копией;
4. по завершении задачи предлагает пользователю сохранить модифицированную
   версию или, возможно, оформить другой скрипт.

Что это даёт:

- высокую степень детерминированности при сохранении возможностей агента;
- меньший расход токенов;
- воспроизводимость флоу без агента.

Размещение: скрипты в идеале должны лежать не в проекте, а в отдельном
репозитории. На прежних этапах для этого придуман `no-launchpad-devkit`
(в текущих материалах репозитория он не зафиксирован — приведён как источник из
прошлых этапов).

Открытые вопросы:

- как версионировать и распространять devkit;
- как схлопывать одноразовые модифицированные копии обратно в devkit;
- как скилл объявляет зависимость от конкретной версии скрипта;
- где проходит граница между скриптом и скиллом;
- как откатывать неудачные модификации, не теряя исходный скрипт.

## Часть 2. Воркспейс для агента

Идея: собрать для проекта своего рода воркспейс, в котором агент работает. В
этом воркспейсе агент ведёт «свои дела» — например, сохраняет кэши.

Текущая проблема: агент часто обращается к внешним директориям.

Оценка: само по себе это не сильно решает вопросы безопасности, но в связке с
виртуализацией будет работать хорошо и без конфликтов с другими проектами.

Открытые вопросы:

- состав воркспейса: кэши, временные артефакты, состояние между сессиями;
- связь с открытым вопросом о сохранении состояния между сессиями из
  `agent-work-model`;
- как воркспейс сочетается с виртуализацией;
- что считается «внешней директорией» и как ограничивать туда доступ;
- как воркспейс соотносится с devkit-скриптами из части 1.
