# LLM Wiki Skills (Project-Local)

Общая заметка вне эксперимента. Backlog: проектные Agent Skills для работы с LLM Wiki.

## Требование

Добавить локальные на проекте скиллы OpenCode для типовых операций LLM Wiki,
чтобы модель подтягивала свежий контекст по требованию и не путалась на больших
контекстах.

## Зачем

- Скиллы загружаются on-demand через `skill` tool: агент видит только name и
  description, а полный текст подтягивает при вызове.
- Правила не дублируются в системный контекст целиком — меньше шума и устаревания.
- Один скилл — одна операция: модель реже смешивает сценарии.

## Где размещать

Проектные скиллы OpenCode:

- `.opencode/skills/<name>/SKILL.md` — основной путь;
- также поддерживаются `.agents/skills/<name>/SKILL.md` и
  `.claude/skills/<name>/SKILL.md`.

Discovery идёт вверх от рабочей директории до git worktree.

Требования к файлу:

- YAML frontmatter, обязательны `name` и `description`;
- `name` по regex `^[a-z0-9]+(-[a-z0-9]+)*$`, совпадает с именем директории;
- `description` 1–1024 символа и достаточно конкретный, чтобы агент выбрал скилл.

## Кандидаты скиллов

1. `wiki-note` — записать заметку в активный эксперимент или глобально
   (`outputs/shared/notes/`). Реализует routing: контекст эксперимента
   приоритетен, `shared` только по явному запросу, при неоднозначности — спросить.
2. `wiki-experiment` — начать или закрыть эксперимент: создать
   `outputs/experiments/<slug>/` с `README.md` и `history.md`, обновить
   `outputs/history.md`.
3. `wiki-ingest` — ingest источника из `raw/` в `wiki/`: summary, concept/entity
   страницы, `[[wikilinks]]`, обновление `index.md`, `source_notes.md`, `log.md`.
4. `wiki-query` — ответ по wiki, затем по `raw/` при необходимости, с цитатами;
   предложить crystallization.
5. `wiki-crystallization` — сначала статья в `outputs/`, затем предложение
   добавить в `wiki/`.
6. `wiki-lint` — health-check: битые `[[wikilinks]]`, orphans, устаревшие claims,
   дубликаты, missing sources; только отчёт.

## Ограничения

- `WIKI_LLM.md` остаётся единственной схемой. Скиллы ссылаются на неё, а не
  копируют правила.
- `raw/` неизменяем; `outputs/` пишется только по явному запросу.
- Один скилл — одна ответственность; без кросс-зависимостей между скиллами.
- При необходимости ограничить доступ через `permission.skill` в `opencode.jsonc`.
- Образец структуры — глобальный скилл `init-ts-project`.

## Критерий приёмки

- `skill` tool перечисляет скиллы с корректными description.
- `wiki-note` пишет заметку в правильное место без лишних вопросов и спрашивает
  при неоднозначности.
- `wiki-ingest` обновляет index/source_notes/log и не трогает `raw/`.
- `wiki-lint` не изменяет контент, только сообщает.
- Нет расхождений с `WIKI_LLM.md` и `.agents/*`.
