# Stitch Skills Research

Общая заметка вне эксперимента. Ресёрч: что такое Google Stitch и что из
репозитория [google-labs-code/stitch-skills](https://github.com/google-labs-code/stitch-skills)
можно перенести в наш флоу без самого Stitch.

Источник: `https://github.com/google-labs-code/stitch-skills` (Apache-2.0,
официально не поддерживаемый Google продукт).

Покрытие: прочитаны README, дерево файлов и ключевые `SKILL.md`
(`extract-design-md`, `design-md`, `react-components`, `stitch-loop` с
`baton-schema`, `taste-design`), CI-валидация и `validate.js`. Часть скиллов
(`react-native`, `remotion`, `shadcn-ui`, `generate-design`, `enhance-prompt`,
`site-md`, `manage-design-system`) оценена по структуре и описанию, не целиком.

## Что такое Google Stitch

- Инструмент Google Labs для генерации UI: из текста или изображения создаёт
  экраны и отдаёт их как HTML/CSS. Веб-приложение — `stitch.withgoogle.com`,
  плюс MCP-сервер для подключения к агентам.
- `stitch-skills` — не сам Stitch, а библиотека Agent Skills вокруг него по
  открытому стандарту Agent Skills. Совместим с Codex, Claude Code, Cursor,
  OpenCode (ручная установка).
- Три плагина: `stitch-design` (генерация и управление дизайном),
  `stitch-build` (превращение дизайнов в код), `stitch-utilities`
  (вспомогательные скиллы).

## Как устроены их скиллы

```text
skills/<skill-name>/
├── SKILL.md       — фазы, гейты, анти-паттерны
├── scripts/       — исполняемые проверки и сеть (validate.js, fetch-stitch.sh)
├── resources/     — база знаний (чеклисты, шаблоны, style-guide.json)
└── examples/      — эталонный «gold standard» пример
```

Плюс `plugin.json`, `marketplace.json` и CI, который запускает валидатор на
эталонном примере.

## Что переносимо без Stitch

| Идея | Переносимость | Как ложится на наш флоу |
|---|---|---|
| Каркас скилла: `SKILL.md` + `scripts/` + `resources/` + `examples/` | Да | Добавить в свои скиллы базу знаний, исполняемые скрипты и эталонные примеры; сейчас в основном только текст `SKILL.md` |
| Гейты, обязательные фазы, анти-паттерны | Да | Усиливает skills и смягчает проблему «агент не дочитал правило» |
| Исполняемые проверки вместо прозы (`validate.js` на AST) и CI на эталонном примере | Да | Совпадает с идеей исполняемых правил и `no-launchpad-devkit` |
| `resources/` как база знаний, `examples/` как эталон | Да | Детали подтягиваются по требованию — меньше токенов |
| `DESIGN.md` как единый источник истины дизайна | Да | Аналог описания нашей дизайн-системы (foundation-токены и пресеты) |
| Процесс `extract-design-md` (детект стека, фазы, чеклист качества, описательные имена цветов с hex) | Да | Извлечение дизайн-языка из нашего кода PandaCSS; фаза извлечения не требует Stitch |
| `taste-design`: жёсткие правила и явный список запретов (anti-slop) | Частично | Мнения спорные, но формат «явные bans» переносится |
| `stitch-loop`: файлы состояния (`SITE.md`, `next-prompt.md` — эстафета, `metadata.json`, staging) | Да (паттерн) | Закрывает открытый вопрос о состоянии между сессиями; сам Stitch-шаг не переносится |
| `react-components`: architecture-checklist, component-template, общий `style-guide.json` как контракт токенов | Да | Образец для наших конвенций компонентов |
| `enhance-prompt`, `site-md`, framework-скиллы | Частично | Идеи и структура, не сам код |
| MCP-вызовы (`generate_screen`, `get_screen`, `upload`, `manage-design-system`) | Нет | Требует Stitch MCP; прямой замены в нашем флоу нет |

## Ключевой вывод

Ценность репозитория — не привязка к Stitch, а инженерные паттерны вокруг
скиллов:

1. Скилл = инструкция + исполняемые проверки + база знаний + эталонный пример.
2. Правило подкреплено скриптом и CI, а не только текстом.
3. Состояние между итерациями живёт в файлах (эстафета, роадмап, метаданные).
4. Описательный «дизайн-язык» как единый источник истины.

Слой генерации экранов и MCP не нужен: наш флоу порождает компоненты из
собственной дизайн-системы в коде.

## Ограничения и риски

- Половина репозитория (генерация дизайна) без Stitch не воспроизводится;
  переносятся паттерны, а не флоу целиком.
- `DESIGN.md` оптимизирован под LLM-генератор экранов, а не под нашу сборку.
- Apache-2.0: идеи свободны; при копировании файлов нужно сохранять лицензию и
  атрибуцию.
- OpenCode требует kebab-case имён скиллов и игнорирует `allowed-tools`.
- Покрытие неполное: часть скиллов оценена по описанию.
