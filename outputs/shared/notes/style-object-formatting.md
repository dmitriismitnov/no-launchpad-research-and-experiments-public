# Style Object Formatting: One Property Per Line

Общая заметка вне эксперимента. Backlog-правило для тулинга.

## Требование

Каждое property объекта стилей должно быть на отдельной строке.

Под «объектом стилей» понимаются:

- аргументы `css({ ... })` в `src/`;
- `base`, `variants`, `compoundVariants`, `defaultVariants` в recipe/slot recipe;
- token-фрагменты foundation;
- любые другие объекты, описывающие визуальные правила.

## Зачем

- Property-local conditions (`backgroundColor._light._hover`) читаются и
  ревьюятся только когда каждое свойство на своей строке.
- Диффы не смешивают перестановку и изменение значений.
- Проще проверять правило «только longhand properties».

## Ограничение проекта

Действующее правило: **dprint владеет форматированием, ESLint — quality**.
Style-only правило не должно уходить в ESLint без причины.

## Кандидаты реализации

1. **dprint TypeScript.** Проверить, есть ли опция, форсирующая многострочность
   object expressions (аналог `objectExpression.preferSingleLine`). Если dprint
   уже сохраняет авторские переводы строк в объектах, правило может работать
   только через дисциплину записи, без конфигурации. Предпочтительный путь, так
   как не нарушает разделение форматирования и quality.
2. **ESLint `object-property-newline`.** Надёжно форсирует свойства на отдельных
   строках. Если использовать, то только на `src/**/*.{ts,tsx}` и с пометкой как
   исключение из правила о владении форматированием.

## Ограничения

- Сгенерированный `src/shared/styled-system/` исключён из проверок.
- Не трогать JSON-конфиги и `manifest.json`.
- Изменение не должно добавлять новые mise-задачи.

## Критерий приёмки

- `mise run check` падает, если два свойства стиля стоят на одной строке.
- `mise run fix:all` приводит такие объекты к одной строке на свойство.
- Правило синхронизировано в `.agents/tooling.md` и, при использовании ESLint,
  в `eslint.config.mjs`.
