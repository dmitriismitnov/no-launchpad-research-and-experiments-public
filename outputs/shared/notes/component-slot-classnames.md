# Component Slot ClassNames

Общая заметка вне эксперимента. Backlog: расширение escape-hatch API компонентов.

## Требование

Сейчас публичный `className` применяется только к root-элементу компонента. Это удобно и обычно достаточно, но теряется анатомия: потребитель влияет на компонент целиком и не может адресно настроить внутренние части.

Хочется дать `className` по слотам анатомии — это закрыло бы множество потенциальных кейсов без введения новых визуальных пропсов.

## Пример: Button

Анатомия уже описана в recipe: `root / prefixIcon / label / suffixIcon`.

```tsx
<Button
    prefixIcon="check"
    classNames={{
        root: css({ /* ... */ }),
        prefixIcon: css({ /* ... */ }),
        label: css({ /* ... */ }),
        suffixIcon: css({ /* ... */ }),
    }}
>
    Continue
</Button>
```

PandaCSS это поддерживает естественно: `button({ tone, size })` возвращает стили по слотам, и результирующие классы просто мержатся со слот-специфичными.

## Зачем

- Адресная правка одного слота без обёрток и без `!important`.
- Остаётся один явный escape hatch вместо роста числа визуальных пропсов (`labelClassName`, `iconClassName`, …).
- Слоты уже зафиксированы в recipe и тестируются, поэтому контракт не размывается.
- Хорошо сочетается с требованием «компонент владеет своей проекцией»: потребитель точечно переопределяет, а не переписывает.

## Открытые вопросы

- Имя: `classNames` (plural, слот-мапа) против сохранения одиночного `className` для root. Вероятно, оба: `className` = root, `classNames` = слоты.
- Типизация: `Partial<Record<Slot, string>>`, выведенная из анатомии recipe, чтобы набор ключей совпадал со слотами.
- Слоты как контракт: изменение анатомии становится изменением публичного типа — нужно осознанно.
- Нужны ли слоты, у которых нет собственного элемента (сейчас у `Button` все четыре материальны).
- Применимость ко всем компонентам или только к slot-based; для single-root (`Icon`) схема вырождается в текущий `className`.

## Замечание по сути

Идея ложится ровно на существующую slot-модель Panda, так что реализация, скорее всего, сведётся к типу `classNames` и мержу классов на уже существующих значениях из `button({ tone, size })` — без изменений в recipe. Главное решение — считать ли набор слотов публичным контрактом.
