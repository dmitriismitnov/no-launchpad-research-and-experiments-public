# Artifact Separation Review

Общая заметка вне эксперимента. Backlog: ревью кода на разделение артефактов.

## Требование

Провести ревью кодовой базы и убрать экспорты, которые нужны только Storybook
(или другому tooling), из production-модулей компонентов и foundation.

Если значение/константа/тип существует только ради story, галереи или теста,
он не должен экспортироваться из файла компонента или foundation. Story-only
код живёт рядом со story, а не в публичном API модуля.

## Зачем

- Публичный экспорт — это контракт. Story-only артефакт в нём создаёт ложное
  впечатление полезности и мешает оценить реальную поверхность API.
- Knip и будущие потребители видят лишние export'ы как «используемые», поэтому
  мёртвые/сугубо-инструментальные сущности не всплывают.
- Легче удалять и менять внутренности, если наружу не торчит деталь ради
  галереи.

## Что считается нарушением

- `export` из файла компонента/foundation, у которого единственный потребитель —
  `*.stories.tsx`, visual test или внутренняя галерея.
- Manifest-списки ключей, дублирующие структуру данных только чтобы Storybook
  мог их перебрать.
- Типы и helper'ы, нужные лишь для рендера story.

Не нарушение: экспорт, который использует и код приложения, и story; публичный
тип/константа с реальным внешним потребителем.

## Пример из последнего ревью

`src/shared/styles/foundation/colors/semantic.ts:29`:

```ts
export const SEMANTIC_SHADOW_STEPS = [ 100, 200, 300, 400, 500, 600, 700, 800, ] as const;
```

- Это не часть context-матрицы, а ручной manifest ключей specialized domain
  `colors.semantic.shadow.*`.
- Экспортируется из foundation и реэкспортируется через
  `colors/index.ts` и `foundation/index.ts`.
- Единственный потребитель — `src/shared/styles/foundation/Colors.stories.tsx`
  (рендер shadow swatches). Button использует литерал
  `{colors.semantic.shadow.300}`, а не эту константу.
- Риск: список вручную дублирует ключи внутри `semanticColors.shadow`; при
  добавлении/удалении уровня можно рассинхронизировать объект и manifest,
  и Storybook молча не покажет изменение.

## Кандидаты решения

1. Перенести список в story-слой: объявить его в `Colors.stories.tsx` (или в
   общем story-helper), убрать из `semantic.ts` и barrels. Предпочтительно, если
   никому вне story список не нужен.
2. Выводить список из самих данных (`Object.keys(semanticColors.semantic.shadow)`)
   внутри story — убирает дублирование источника истины.
3. Если список понадобится другим инструментам, оставить его в foundation, но
   явно задокументировать потребителя, а не держать «на всякий случай».

## Критерий приёмки

- Нет экспортов из `src/app`/`src/shared`, чей единственный потребитель — story,
  visual test или внутренняя галерея.
- `SEMANTIC_SHADOW_STEPS` (или его замена) недоступен в публичном API foundation,
  если он не нужен вне Storybook.
- `mise run check`, `check:deps`, `storybook:build` проходят; Storybook
  по-прежнему показывает полный набор `shadow.*`.

## Статус

Backlog. Общее правило ревью, не привязано к активному эксперименту.
